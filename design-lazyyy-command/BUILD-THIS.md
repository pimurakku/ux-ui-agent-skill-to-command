# สร้างระบบนี้ขึ้นมาใหม่ — ข้อกำหนดและกับดักทั้งหมด

> ไฟล์นี้คือ **โจทย์เต็ม** ของ Mission Control พร้อมทุกอย่างที่พังระหว่างทางและวิธีที่แก้ได้จริง
> ส่งไฟล์นี้ให้ agent แล้วมันควรสร้างระบบเดียวกันได้โดยไม่ต้องเจ็บซ้ำ
>
> ส่วนที่มีค่าที่สุดไม่ใช่ข้อกำหนด แต่คือ **หัวข้อ "กับดัก"** — ทุกข้อในนั้นเกิดขึ้นจริง
> ส่วนใหญ่ผ่าน syntax check ได้สบาย และโผล่ตอนรันจริงเท่านั้น

---

## 1 · ระบบนี้คืออะไร

ห้องบัญชาการที่ดูการทำงานของ agent หลายตำแหน่งในสายงานเดียว **ตามเหตุการณ์จริงใน
Claude Code** ไม่ใช่แอนิเมชันที่เขียนสคริปต์ไว้

ตัวละครหนึ่งตัว = agent หนึ่งตำแหน่ง พอถูกเรียกก็สว่างขึ้น ขึ้นชื่อไฟล์ที่กำลังเขียน
เดินไปกลางห้อง ส่งงาน แล้วดับลง มีคะแนน มีด่านตรวจ มีคำตัดสินว่างานใช้ได้หรือไม่

**สิ่งที่ห้ามทำเด็ดขาด** — ห้ามแสดงอะไรที่ไม่ได้เกิดขึ้นจริง
ห้องที่เงียบต้องแปลว่าสายงานเงียบ ไม่ใช่ห้องเสีย

## 4 · กับดัก — ทุกข้อเกิดขึ้นจริง

### 4.1 ไม่มีชื่อเครื่องมือสำหรับการเรียก subagent

ดัก `PreToolUse` ที่ชื่อ `Task` หรือ `Agent` **จะเงียบสนิท** เอกสารระบุว่า
*"Subagents/Tasks: No specific tool name; dispatch via SubagentStart and TaskCreated"*

ของจริงคือ `SubagentStart` / `SubagentStop` โดย matcher เป็น **ชื่อ agent**
และ hook ที่ยิงจากข้างใน subagent **พก `agent_type` ติดมาด้วย** —
นี่คือวิธีผูก "ไฟล์นี้ใครเขียน" เข้ากับตัวละครที่ถูกตัว

### 4.2 macOS symlink ทำให้ path เหลือแค่ชื่อไฟล์

`/var` กับ `/tmp` เป็น symlink ของ `/private/...` ถ้าไม่ `.resolve()` ทั้งสองฝั่ง
ก่อนเทียบ `relative_to` จะพลาดแล้วตกไปใช้แค่ basename

ผลคือการแยกโต๊ะด้วย path (`src/` กับ `server/`) **พังเงียบ ๆ**
selftest จับได้ ถ้าไม่มี selftest จะไม่มีใครรู้

### 4.3 ตัวรับ hook ห้ามคืนค่าที่ไม่ใช่ 0

exit code ที่ไม่ใช่ 0 จะพิมพ์ข้อความผิดพลาดลงในบทสนทนาของนักเรียน
เสียเฟรมหนึ่งเฟรมของแอนิเมชันนั้นถูก ทำให้ทุกคำสั่งในคาบดูเหมือนพังนั้นแพง

ครอบ `try/except` ทุกทาง แล้ว `sys.exit(0)` เสมอ · ทดสอบด้วยการป้อน JSON พัง ๆ เข้าไป

### 4.4 hooks อ่านตอนเปิด session เท่านั้น

session ที่เปิดค้างอยู่ตั้งแต่ก่อนแก้ `.claude/settings.json` **จะไม่ส่งอะไรเลย**
ทดสอบด้วย session ใหม่เสมอ (`claude -p` นับเป็น session ใหม่)

### 4.5 โหมด headless ค้างตายเพราะรอขออนุญาต

ถ้า `project/` เป็น symlink ชี้ออกนอกโฟลเดอร์ทำงาน การเขียนผ่านมันจะขออนุญาต
และในโหมด `-p` **ไม่มีใครกดอนุมัติ มันจะค้างตลอดกาล**

แก้ด้วย `--add-dir <workspace>` · อาการคือ process ยังอยู่แต่ไม่มีเหตุการณ์ใหม่เลย
ตรวจด้วยการ `grep -c 'requested permissions'` ใน transcript

### 4.6 ตัวตรวจที่ฝังรหัสโครงการไว้ = ประตูที่เงียบ

`correcter` มี `WKO` ฝังในตัวอักษร (`SRS-WKO-001`, `[A-Z]{2,4}-WKO-\d+`)
พอชี้ไปโปรเจกต์อื่น **หาเอกสารไม่เจอ คืนรายการว่าง แล้วรายงาน `VERIFIED` เหมือนเดิม**

> ประตูที่เงียบเพราะหาของไม่เจอ อันตรายกว่าประตูที่ตก
> เพราะประตูที่ตกมีคนไปดู ส่วนประตูที่เงียบไม่มีใครรู้ว่ามันเลิกทำงานไปแล้ว

ทดสอบตัวตรวจทุกตัวด้วยโปรเจกต์เปล่า — ถ้ามันผ่าน แปลว่ามันไม่ได้ตรวจอะไร

### 4.7 ปล่อยให้ agent ตัวเดียวถือทั้งสายงาน = ไม่ได้อะไรเลย

ให้ orchestrator ตัดสินใจเองว่าจะอ่านนานแค่ไหน ผลคือ **6 นาที 0 ไฟล์**
มันอ่าน correcter ทั้งตัวและทุก skill ก่อนลงมือ

แก้สองชั้น
1. **shell ถือลำดับระยะ** เรียก agent ทีละบทบาท แต่ละตัวได้งานเดียว
2. **บอก path ตรง ๆ** ทุกไฟล์ที่ต้องใช้ พร้อมสั่งห้ามรัน `ls -R` `find` `grep -r`

หลังแก้: ได้ PRD 377 บรรทัดในรอบเดียว

### 4.8 อย่าแก้ bash script ที่กำลังรัน

bash อ่านไฟล์ทีละส่วนขณะทำงาน แก้กลางคันแล้วมันอาจอ่านไบต์เพี้ยน
หยุดก่อนแก้ทุกครั้ง (ผมทำผิดข้อนี้เองสองรอบ)

### 4.9 SSE ต้องต่อใหม่เอง และต้องส่งประวัติย้อนหลัง

- รีสตาร์ทเซิร์ฟเวอร์ = หน้าเว็บค้างถาวร ถ้าไม่เขียน reconnect (เขียนแค่ข้อความว่า
  "ขาดการเชื่อมต่อ" ไม่พอ)
- เปิดหน้าเว็บกลางรัน = จอว่าง ถ้าไม่ส่ง log ย้อนหลังตอนต่อ ซึ่งเป็นจังหวะที่คนเปิดบ่อยที่สุด

### 4.10 ภาพที่ "พื้นโปร่ง" อาจไม่โปร่งจริง

ภาพจาก AI ที่ดูเหมือนพื้นโปร่ง มักเป็น **ลายตารางหมากรุกที่อบมาในพิกเซล**
(colortype=2 ไม่มี alpha สลับค่า ~254 กับ ~240)

และ **ห้ามคีย์สีขาวทั้งภาพ** เพราะตัวละครมีสีขาวอยู่ในตัว (เสื้อยืด เครื่องหมายถูก)
จะโดนเจาะทะลุ

วิธีที่ถูกคือ **flood fill จากขอบภาพ** — ขาวที่ต่อเนื่องกับขอบเท่านั้นที่เป็นพื้นหลัง
ถ้าตัวละครยืนชิดกันจนไม่มีช่องคั่น ให้หาจุดที่พิกเซลบางที่สุดแล้วผ่าตรงนั้น

### 4.11 CSS `display` ทับ `[hidden]`

`#form { display:flex }` ชนะ `hidden` ของ browser ฟอร์มเลยโผล่พร้อมรายการที่มันควรแทนที่
ต้องเขียน `[hidden]{display:none !important}`

### 4.12 อะไรที่อยู่ใน element ที่ถูก `scaleX(-1)` จะกลับด้านหมด

พลิกตัวละครให้หันไปทางที่เดิน แล้วตัวเลข `+10` ที่อยู่ข้างในกลับหัวไปด้วย
ย้ายออกมานอก element ที่พลิก

### 4.13 การ์ดลอยหลายใบ = ปัญหาที่แก้ด้วยการดันไม่ได้

11 โต๊ะ แต่ละโต๊ะมีการ์ดลอย = ชนกันแน่นอน ดันแล้วก็ไปชนที่อื่น

แก้ที่หลักการ: **การ์ดรายละเอียดมีได้ใบเดียว** (ตัวที่ขยับล่าสุด)
ที่เหลือไปอยู่ใน **แถบรวมที่จัดวางเป็นรายการ** — ชนไม่ได้ในทางโครงสร้าง

และการ์ดต้องวัดตำแหน่งจาก **หัว** ไม่ใช่จากเท้า ไม่งั้นมันไปทับหน้าตัวละคร

### 4.14 พิกัดตัวละครต้องอิงเวทีคงอัตราส่วน

ถ้าฉากใช้ `background-size: cover` มันจะถูกครอปต่างกันทุกขนาดหน้าต่าง
ตัวละครที่วางด้วย % ของ viewport จะหลุดจากโต๊ะทันทีที่เปลี่ยนขนาดจอ

ทำเวทีเป็นกล่องอัตราส่วนคงที่ (`min(100vw, 100vh * ratio)`) วางกลางจอ
แล้วพิกัดทุกตัวเป็น % ของเวทีนั้น

### 4.15 ตัวแปรที่ลบไปแล้วแต่ยังถูกอ้าง = เซิร์ฟเวอร์ตายตอนกดปุ่ม

`ReferenceError: brief is not defined` — ผ่าน `node --check` สบาย
พังตอนกดปุ่มจริงเท่านั้น **ต้องกดปุ่มจริง อย่าตรวจแค่ syntax**

### 4.16 อย่าโชว์ปุ่มที่กดแล้วไม่เกิดอะไร

ปุ่มเล่นซ้ำ (⏮ ⏸ ½× 2×) เป็นของโหมด replay ปล่อยให้โชว์ในโหมดสดแบบกดไม่ได้
คนอ่านว่า "หยุดงานจริงได้" ซึ่งไม่จริง — **ซ่อนไปเลย**

เช่นเดียวกับกล่องที่บอกว่า "ยังไม่มีคำตัดสิน" — กล่องที่รายงานว่าไม่มีข่าว ไม่ควรมี

### 4.17 ปุ่มต้องรู้สถานะงานที่ตัวเองไม่ได้เริ่ม

ถ้าสั่งงานจาก terminal ปุ่มยังขึ้นว่า "เริ่ม" ทั้งที่งานเดินอยู่
ให้สคริปต์ **ประกาศสถานะตัวเองลง event log** ห้องจะรู้ไม่ว่าใครสั่ง

### 4.18 บรรทัดใน feed ต้องบรรทัดเดียว

ปล่อยให้คำสั่ง shell ตัดบรรทัดเอง = 4 บรรทัดของ path ยาว ๆ ดันทุกอย่างตกจอ
ตัดท้ายด้วย ellipsis ใส่ข้อความเต็มไว้ใน `title` และตัด prefix ที่ไม่ให้ข้อมูล
(`cd /Users/...;`) ออก

### 4.19 codex exec ไม่มีเครื่องมือสร้างภาพ

ยืนยันแล้วสามทาง: ไม่มีใน tool list · `tool_search` คืนค่าว่าง ·
CLI `imagegen` ต้องใช้ `OPENAI_API_KEY` ที่บัญชีแบบ ChatGPT ไม่มี

วิธีที่ใช้ได้คือสร้างในเบราว์เซอร์ แล้วโอนไฟล์ผ่าน **คลิปบอร์ด** —
เพราะดาวน์โหลดถูกบล็อกในโหมดอัตโนมัติ และ CSP บล็อกการ POST ไป localhost

```js
// ในหน้าเว็บ: ต้องเรียกภายใน click จริง ไม่งั้น NotAllowedError
navigator.clipboard.writeText(base64)
```
```sh
pbpaste > f.b64 && base64 -d -i f.b64 -o out.png   # macOS ต้องใช้ -i/-o
```

### 4.20 ขนาดตัวละครอิงหน้าต่าง แต่พิกัดอิงเวที = ตัวโตหลุดเบาะทันทีที่จอไม่ใช่ 3:2

ข้อ 4.14 แก้เรื่อง **ตำแหน่ง** ไปแล้ว แต่ **ขนาด** ยังเขียนเป็น `21.5vh` ซึ่งวัดจากหน้าต่าง
ไม่ใช่จากเวทีที่ถูกคาดดำ

จอ 3:2 พอดีจะไม่เห็นอะไรเลยเพราะสองค่าเท่ากัน · พอเป็นจอสูง เวทีเตี้ยลงแต่ `vh` ไม่ลด
ตัวละครจึงโตขึ้นเมื่อเทียบกับเบาะที่มันยืน — เท้าอยู่ที่เดิม แต่ตัวล้นออกไป

แก้ด้วยการประกาศความสูงเวทีเป็นตัวแปรแล้วคิดขนาดจากมัน

```css
#room{ --stage-h:min(100vh, calc(100vw / 1.5)); }
.station{ --figbase:calc(var(--stage-h) * .215); }
```

วัดจริงสี่ขนาดหน้าต่าง (1440×960 · 1100×900 · 1600×760 · 900×1200) อัตราส่วน
ตัวละครต่อเวทีต้องคงที่ทุกขนาด **ทดสอบด้วยจอเดียวจับข้อนี้ไม่ได้**

### 4.21 ตัดพื้นขาวแล้วเสื้อผ้าสีขาวโปร่งไปด้วย

ตัวตัดเดิมให้ค่าความทึบ `110` กับพิกเซลที่ "ขาวแต่ flood fill ไปไม่ถึง" ซึ่งคือ
**ข้างในตัวละคร** พอดี — ชุดคลุมสีครีม โคมไฟ หน้ากระดาษ กลายเป็นโปร่งครึ่งหนึ่ง

พิกเซลที่ flood fill ไปไม่ถึง คือพื้นหน้า ไม่ใช่พื้นหลัง ต้องทึบเต็ม
(ข้อนี้ต่อจาก 4.10 · หลักเดียวกัน คนละที่)

### 4.22 `import` ที่หลุดเข้าไปอยู่ใน docstring

`cut-crew.py` มี `import pathlib` อยู่บรรทัดที่สองของ docstring — ไม่เคยถูกรัน
และไฟล์นี้ยังฝัง path ของเครื่องคนเขียนไว้เป็นปลายทาง เรียกจากเครื่องอื่นไม่ได้เลย

เครื่องมือที่ไม่มีใครเรียกซ้ำ จะพังเงียบไว้จนถึงวันที่ต้องใช้จริง
**ทุกสคริปต์ต้องรันได้จากที่ตั้งของตัวเอง ไม่ใช่จาก home ของคนเขียน**

### 4.23 โหมดเล่นซ้ำเข้าห้องไม่ได้ เพราะทางเข้าเดียวคือ "เลือกโปรเจกต์"

`--replay` มีไว้ดูห้องโดยไม่ต้องรอ agent จริง แต่หน้า splash ออกได้ทางเดียวคือ
กดโปรเจกต์ในรายการ · clone ใหม่ยังไม่มีโปรเจกต์ จึงตันสนิทในโหมดที่ควรใช้ได้ที่สุด

และปุ่ม ▶ สั่งงานต้องซ่อนตอนเล่นซ้ำ ไม่งั้นกดแล้วสั่งงานจริงขณะจอฉายของที่บันทึกไว้ (ข้อ 4.16)

### 4.24 โฟลเดอร์ที่ยังไม่ถูก "ไว้ใจ" ทำให้ permissions.allow ถูกทิ้งทั้งชุด

รันอัตโนมัติแล้วขึ้นบรรทัดนี้

    Ignoring 11 permissions.allow entries from .claude/settings.json:
    this workspace has not been trusted.

แปลว่ากฎที่อุตส่าห์เขียนไว้ให้ `verify.py` เรียกได้ **ไม่มีผลเลย** — ซึ่งคือรูปแบบ
เดียวกับ RUN-01 แต่มาจากอีกทาง · สายงานจะเดินต่อโดยไม่มีตัวตัดสิน

แก้ด้วยการเปิด Claude Code แบบ interactive ในโฟลเดอร์นั้นหนึ่งครั้งแล้วกดยอมรับ
หรือตั้ง `projects["<path>"].hasTrustDialogAccepted: true` ใน `~/.claude.json`
**ทดสอบทุกครั้งด้วยเครื่องที่ยังไม่เคยเปิดโฟลเดอร์นี้**

### 4.25 `--add-dir` กลืนพรอมป์ที่วางไว้ข้างหลัง

`--add-dir <directories...>` รับหลายค่า พรอมป์ที่ต่อท้ายจึงกลายเป็นชื่อโฟลเดอร์
แล้วตายด้วย `Input must be provided either through stdin or as a prompt argument`

ส่งพรอมป์ทาง **stdin** ไปเลย ปัญหาลำดับอาร์กิวเมนต์หายไปทั้งชั้น

```sh
printf '%s' "$task" | claude -p --agent product-owner --add-dir "$WS"
```

### 4.26 `claude -p --agent <name>` บังคับ `tools:` ให้จริง

ทดลองแล้ว: สั่ง `--agent code-reviewer` ให้เขียนไฟล์ มันตอบ `NO_WRITE_TOOL`
และไม่มีไฟล์เกิดขึ้น

แปลว่าสายงานอัตโนมัติไม่ต้องพึ่ง "ขอความร่วมมือในพรอมป์" อีกต่อไป
กติกา *ผู้ทบทวนไม่แก้ของ* กลายเป็นเรื่องของเครื่องมือ ไม่ใช่วินัย
(ก่อนหน้านี้ pipeline เรียก `claude -p` เปล่า ไฟล์ `.claude/agents/*.md` จึงไม่ถูกโหลดเลย)

### 4.27 ช่องว่างในเทมเพลตที่มีแต่คอมเมนต์ ถูกอ่านเป็น "ค่า"

`project_config` ตัดคอมเมนต์ด้วย `\s+#` ซึ่งต้องมีช่องว่างนำหน้า
แต่ช่องที่ยังไม่ได้กรอกจะเหลือข้อความที่ **ขึ้นต้นด้วย** `#` พอดี

    baseline:                   # วันนี้ค่าเท่าไหร่

ผลคือ `outcome.baseline` คืนค่าว่า `"# วันนี้ค่าเท่าไหร่"` และตัวตรวจรายงานว่า
"ค่าฐาน # วันนี้ค่าเท่าไหร่ · วัดโดย # ใครวัด" — ช่องว่างเปล่ากลายเป็นช่องที่กรอกแล้ว
สำหรับทุกคนที่อ่านค่าไปใช้ต่อ

### 4.28 บันทึกว่าด่านตกเพราะอะไร แล้วด่านก่อนหน้าตกตาม

`GAT-01` กวาดหาอะไรก็ตามที่หน้าตาเหมือนรหัสเอกสารใน `project.yml` ทั้งไฟล์
แล้วบอกว่า "อ้างเอกสารที่ไม่มีอยู่" · แต่บันทึกของด่านที่ตกเขียนเหตุผลไว้ว่า

```yaml
  - id: G2
    result: fail
    missing:
      - ไม่ได้ผลลัพธ์ · ไม่พบ project/2-analysis/SRS-DEM-001.md
```

รอบถัดมา `G1` จึงตกด้วยเหตุผลว่า *อ้าง SRS-DEM-001 ที่ไม่มีอยู่* ทั้งที่ PRD อยู่ครบ
**การบันทึกว่าอะไรพัง กลายเป็นสิ่งที่ทำให้พังต่อ** และทางออกเดียวที่เหลือคือลบประวัติทิ้ง
ซึ่งเป็นสิ่งเดียวที่กติกาของด่านห้ามไว้

เฉพาะ `evidence:` ของด่านที่ **ผ่าน** เท่านั้นที่เป็นคำกล่าวว่า "ของชิ้นนี้มีอยู่"
ส่วน `missing:` เป็นคำกล่าวตรงกันข้าม · ตัวตรวจที่อ่านสองอย่างนี้เหมือนกัน คือตัวตรวจที่อ่านไม่ออก

### 4.29 การ์ดที่เปิดเองตอนบทบาททำงาน ไปยืนทับหน้าตัวข้าง ๆ

การ์ดรายละเอียดกว้าง 236px เปิดเองทุกครั้งที่บทบาทเริ่มทำงาน และค้างไว้ตลอดที่มันทำ
โดยที่ไม่มีใครขอดู · ในห้องที่ตัวละครยืนห่างกัน ~145px มันจึงทับหน้าตัวข้าง ๆ ตลอดเวลา

แก้สามชั้น
1. **เปิดเมื่อชี้เมาส์เท่านั้น** — ใครกำลังทำงานบอกไว้แล้วสองที่ที่ไม่บังอะไร (แถบซ้ายล่างกับฟีด)
2. **กางออกด้านที่ไม่มีใครยืน** — แถวหลังกางขึ้น (เป็นผนังกับหน้าต่าง) แถวหน้ากางลง (เป็นพื้นว่าง)
   ของเดิมสลับกันพอดี คือกางเข้าหาอีกแถวทั้งสองทาง
3. **วัดจาก DOM ว่าไม่ทับจริง** — บังคับให้ทุกตัวกลับไปยืนที่เบาะก่อนวัด
   เพราะตัวที่กำลังเดินไม่ได้อยู่ที่เดิม และการวัดตอนมันเดินให้ตัวเลขที่เปลี่ยนทุกครั้งที่รัน

### 4.30 โควตาหมด ถูกบันทึกเป็น "ด่านตก"

ระยะ `design` เจอ `You've hit your session limit · resets 3:50pm` สายงานเห็นแค่ว่า
"ไม่มีไฟล์ที่สั่งให้เขียน" จึงรีทราย ชนกำแพงเดิม แล้วบันทึก **G3 ตกสามครั้ง**
ทั้งที่ยังไม่มีใครตัดสินงานนั้นเลยสักครั้ง

บันทึกที่ผิดแบบนี้แพงกว่าที่คิด เพราะกติกาห้ามลบประวัติของด่าน — ของที่เขียนผิดลงไปจะอยู่ถาวร
และรอบถัดไปก็อ่านมันเป็นความจริง

แยกให้ออกสองอย่างที่หน้าตาเหมือนกันแต่คนละเรื่อง
- **งานไม่ผ่าน** → บันทึกด่านตก แล้วหยุด
- **รันไม่ได้** (โควตา · เครือข่าย · เครื่องมือหาย) → **ห้ามบันทึกผลของด่าน** เพราะยังไม่ได้ตรวจ
  หยุดแล้วบอกว่าเป็นเรื่องอะไร

### 4.31 `set -o pipefail` กลบผลของ `grep`

ในตัวทดสอบเขียนไว้ว่า

```sh
python3 tools/correcter/verify.py --gate G4 --brief | grep -q TRC-01 && ok || bad
```

`verify.py` ออกด้วยรหัส 2 เป็นปกติ (BLOCKED) · `pipefail` ทำให้ทั้งท่อคืน 2
แม้ `grep` จะเจอของที่หาอยู่ **ตัวทดสอบจึงรายงานว่าตก ทั้งที่ของจริงถูก**
เก็บผลใส่ตัวแปรก่อนแล้วค่อย `case` ดู — อย่าต่อท่อจากคำสั่งที่ใช้รหัสออกสื่อความหมาย

### 4.32 `<svg>` ที่ `position:absolute; inset:0` ไม่ยืดเต็มพ่อแม่ — มันยึดขนาดในตัวเอง

`#wires` (เส้นสั่งงานที่วิ่งระหว่างโต๊ะ) เขียนไว้ว่า

```css
#wires{position:absolute; inset:0; ...}
```

หน้าตาเหมือนจะเต็มพ่อแม่แน่นอน แต่ `<svg>` เป็น **replaced element** — กฎ CSS ของอิลิเมนต์กลุ่มนี้
ต่างจาก `<div>` ตรงที่ตอน `width`/`height` เป็น `auto` (ซึ่งเป็นค่าเริ่มต้นเมื่อไม่ได้ตั้งไว้)
มันใช้ **ขนาดในตัวของมันเอง** ไม่ใช่ขนาดจาก `inset:0` — และขนาดในตัวของ `<svg>` ที่ไม่มี
แอตทริบิวต์ `width`/`height` คือ **300×150px ตามสเปก** เสมอ ไม่ว่าพ่อแม่จะใหญ่แค่ไหน

ผลคือ `wire()` อ่าน `wires.getBoundingClientRect()` มาคำนวณพิกัดทุกครั้ง — พิกัดเปอร์เซ็นต์ที่ควร
หมายถึง "ทั้งเวที" กลายเป็นเปอร์เซ็นต์ของกล่อง 300×150 ที่หนีบอยู่มุมซ้ายบนแทน เส้นทุกเส้นที่เคยวาด
จึงไปกระจุกอยู่ในกรอบเล็ก ๆ มุมห้อง ไม่ใช่พาดข้ามห้องจริงตามที่ตั้งใจ — **ตั้งแต่โค้ดชุดนี้ถูกเขียนมา**
ไม่เคยมีเส้นไหนอยู่ถูกที่เลยสักเส้น เพราะเส้นบาง ๆ ในมุมที่ไม่มีใครมองหา ไม่มีใครสังเกตเห็น

แก้ด้วยการใส่ `width:100%; height:100%` ให้ชัดเจน (`inset:0` เก็บไว้ก็ได้ แต่ไม่ได้ทำอะไรจริง)

**ทดสอบด้วยการวัด `getBoundingClientRect()` เทียบกับพ่อแม่** ไม่ใช่แค่มองว่าเส้นโผล่มาบ้างหรือเปล่า
เพราะ `overflow:visible` ทำให้บางเส้นยัง "โผล่มาให้เห็น" ได้แม้กล่องเล็กผิดปกติ — เห็นว่ามีเส้น
ไม่ได้แปลว่าเส้นอยู่ถูกตำแหน่ง

## 7 · สิ่งที่ห้ามทำ

- **ห้ามเดาแทนคนใช้** — ไม่รู้ให้เขียน `TBD — ต้องการ [คน/ข้อมูล]`
  ข้อกำหนดที่แต่งขึ้นแย่กว่าช่องว่าง เพราะช่องว่างมีคนมาเติม แต่ของที่แต่งขึ้นถูกสร้างต่อ

  สายงานที่ผ่านได้เสมอ คือสายงานที่ไม่ได้พิสูจน์อะไร
- **ห้ามรายงานว่าเสร็จโดยไม่ได้ลอง** — ถ้ายังไม่ได้กด ให้บอกว่ายังไม่ได้กด
- **ห้ามสรุปจากสัญญาณเดียว** — `git diff` ว่างไม่ได้แปลว่าไฟล์ไม่ถูกแก้
  (ไฟล์นั้นอาจไม่เคยถูก track) เปิดของจริงดูเสมอ
