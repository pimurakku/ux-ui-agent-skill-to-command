## ชุดภาพปัจจุบัน

ฉากเป็นห้องไม้สไตล์ญี่ปุ่น แสงกลางวัน มีเบาะรองนั่งกลม **11 ใบ**
**5 ใบบนยกพื้นด้านหลัง** และ **6 ใบบนพื้นห้องด้านหน้า** — เท่ากับจำนวนบทบาทพอดี
ตัวละครเป็นแมวการ์ตูน 3 มิติ ยืนเต็มตัวเห็นเท้า ท่าเดียวกันทุกตัว และ**ถือของที่บอกหน้าที่ของตัวเอง**

| ตัวละคร | ของที่ถือ | เบาะ | บทบาท |
|---|---|---|---|
| THE VISIONARY | ม้วนแผนที่เส้นทาง | หลัง · เขียว | Product Owner |
| TIME MARSHAL | นาฬิกาพก | หลัง · ชมพู | Project Manager |
| FIRST CONTACT | สมุดจดที่มีรูปหู | หลัง · เสื่อทาทามิ | Project Intake |
| SYSTEMS SAGE | แว่น + สมุดผังความสัมพันธ์ | หลัง · ฟ้า | Systems Analyst |
| EXPERIENCE ARCHITECT | พัดตัวอย่างสี | หลัง · แดง | UX/UI Designer |
| THE ARCHIVIST | แว่น + สมุดทะเบียน | หน้า · เขียว | Document Control |
| BUG HUNTER | แว่นขยาย | หน้า · ชมพู | QA |
| THE INTERFACE | กระดานโครงหน้าจอ | หน้า · เสื่อทาทามิ | Frontend Developer |
| THE CORE | กองบล็อกไม้ | หน้า · เหลือง | Backend Developer |
| THE GATEKEEPER | ตราประทับรูปอุ้งเท้า | หน้า · ฟ้า | Lead Reviewer |
| THE LAUNCHER | โคมไฟรูปจรวด | หน้า · แดง | DevOps / Release |

ของที่ถือคือคำอธิบายหน้าที่ที่อ่านได้โดยไม่ต้องมีตัวหนังสือ — ถ้าเปลี่ยนตัวละคร
ให้เลือกของให้ตรงหน้าที่ก่อนเลือกสีหรือชุด

การจับคู่นี้อยู่ใน `tools/monitor/roster.json` ที่เดียว เปลี่ยนคู่ได้ด้วยการตัดแผ่นรวมใหม่
ตามลำดับชื่อที่ต้องการ ไม่ต้องแตะ CSS หรือ JS

### ป้ายชื่อกับการ์ด

- **ป้ายชื่อ = ชื่ออย่างเดียว บรรทัดเดียว หน้าตาเดียวกันทุกตัว**
  พื้นถ่านอุ่น `rgba(38,29,22,.88)` · ตัวอักษรครีม `#F3E9DA` · ไม่ใช้สีประจำบทบาท
  (สีประจำบทบาทยังใช้กับวงแสงที่เท้าและตัวละครตอนทำงาน) · ยศกับชื่อไทยอยู่บนการ์ด
  แถวหน้าอยู่ใต้ตัวละคร · **แถวหลังอยู่เหนือหัว** เพราะใต้เท้าของมันคือหัวของแถวหน้า
- **ไม่มีแผงเรืองแสงหลังตัวละครแล้ว** — ฉากสว่าง แผงกลายเป็นหมอกบังภาพ
  ใครกำลังทำงานดูจากตัวละครที่สว่างขึ้นและวงแสงที่เท้า
- **การ์ดรายละเอียดขึ้นเมื่อเอาเมาส์ชี้เท่านั้น** และกางออกด้านที่ไม่มีใครยืน
  (แถวหลังกางขึ้น แถวหน้ากางลง)
- แถวหลังถูกวาดอยู่**หลัง**แถวหน้าจริง ๆ (`z-index`) ป้ายของมันจึงถูกตัวแถวหน้าบังบางส่วน
  แทนที่จะไปบังหน้าใคร
- ขนาดของกล่องตัวละคร ป้าย และการ์ด คิดจากความสูงของ**เวที** ไม่ใช่ของหน้าต่าง
  จอรูปร่างไหนก็ได้สัดส่วนเดิม

## สร้างฉากใหม่

ข้อกำหนดที่ฉากต้องผ่าน ไม่ใช่แค่ความสวย

```
ภาพแนวนอน 3:2 ขนาด 1536x1024 · ห้องเปล่า มองตรงเข้าไปในห้องระดับสายตา
วางเบาะรองนั่งกลม 11 ใบให้เห็นครบทุกใบ ไม่มีใบไหนบังกัน
  5 ใบบนยกพื้นด้านหลัง · 6 ใบบนพื้นห้องด้านหน้า
  เว้นพื้นโล่งระหว่างสองแถว
เว้นที่ว่างเหนือเบาะทุกใบไว้สำหรับวางตัวละครทีหลัง

ห้ามมีคน · ห้ามมีตัวหนังสือ ตัวเลข ป้ายชื่อ โลโก้ ทุกชนิด
ห้ามมีจอหรือแผงแสดงผลใด ๆ
```

**ทำไมต้องย้ำว่าห้ามมีตัวหนังสือ** — รอบแรกที่ไม่ได้ย้ำ ได้ฉากที่มีป้ายชื่อกับจอ
อบมาในภาพ พอวางตัวละครกับการ์ดข้อมูลทับ กลายเป็นอ่านไม่ออกทั้งจอ

**ทำไมต้อง 3:2 พอดี** — `#room` เป็นเวทีอัตราส่วนคงที่ 3:2 พิกัดตัวละครทุกตัวเป็น
เปอร์เซ็นต์ของ *ภาพ* ไม่ใช่ของหน้าต่าง ภาพอัตราส่วนอื่นจะทำให้ทุกตัวหลุดจากเบาะ

## สร้างทีมงาน

ขอเป็น **แผ่นรวมหลายตัวในภาพเดียว** ไม่ใช่ทีละตัว เพราะตัวละครในภาพเดียวกัน
จะสไตล์ ขนาด และแสงตรงกัน ส่วนภาพที่สร้างแยกกันจะไม่เข้าชุด

```
ภาพแนวนอนใบเดียว ตัวละครเต็มตัวยืนเรียงแถวเดียว ระยะห่างเท่ากัน ขนาดเท่ากันทุกตัว
ท่าเดียวกันทุกตัว: หันสามส่วนสี่ แขนปล่อยข้างตัว เห็นเท้าครบและวางราบกับพื้น
หัวจรดเท้าอยู่ในเฟรม
พื้นหลังขาวล้วน ไม่มีพื้น ไม่มีเงา ไม่มีตัวหนังสือ ไม่มีกรอบ
เว้นช่องว่างสีขาวระหว่างตัวละครแต่ละตัว
```

ช่องว่างระหว่างตัวสำคัญกว่าที่คิด — ตัวตัดใช้คอลัมน์ที่ "บางที่สุด" เป็นรอยผ่า
ถ้ายืนชิดจนแขนเกยกัน รอยผ่าจะกินแขนของตัวข้าง ๆ ไป

## เตรียมไฟล์ตัวละคร

ตัวเดียวต่อหนึ่งไฟล์ (แบบที่ใช้อยู่ตอนนี้)

```sh
python3 tools/monitor/cut-crew.py <ไฟล์ตัวละคร> the-visionary <โฟลเดอร์ปลายทาง>
```

หรือแผ่นรวมหลายตัวในภาพเดียว ใส่ชื่อเรียง **ซ้ายไปขวา** ตามที่ยืน

```sh
python3 tools/monitor/cut-crew.py <แผ่นรวม> id1,id2,id3,id4,id5,id6
```

ชื่อต้องตรงกับ `id` ใน `roster.json` · ใส่โฟลเดอร์ปลายทางเป็นอาร์กิวเมนต์ที่สามได้
ถ้าอยากลองก่อนทับของจริง

**ตัวตัดทำสามอย่างเสมอ**

1. ตัดพื้นหลังออก
2. **ครอบให้พอดีตัว จากหัวจรดเท้า** — ห้องย่อ/ขยายทุกตัวให้สูงเท่ากัน
   ไฟล์ที่เหลือขอบว่างด้านบนจะกลายเป็นตัวละครที่เตี้ยกว่าเพื่อนโดยไม่มีใครตั้งใจ
3. **จัดกึ่งกลางภาพที่ "เท้า" ไม่ใช่ที่กรอบภาพ** — ตัวที่หิ้วโคมไฟออกข้างเดียว
   จุดกึ่งกลางของกรอบจะเยื้องจากจุดที่มันยืนจริง ห้องวางตัวละครด้วยการจัดภาพ
   ให้กึ่งกลางอยู่บนเบาะ มันจึงยืนหลุดแท่นทั้งที่ทุกตัวเลขบอกว่าอยู่ตรงกลาง
   (ของชุดนี้เยื้องกันตั้งแต่ -39 ถึง +49 พิกเซล)

**สิ่งที่ตัวตัดแก้ให้ไม่ได้เหมือนกัน — ลำตัวเอนแม้เท้าจะกลางแล้ว**

ข้อ 3 จัดกึ่งกลาง "เท้า" ให้แล้ว แต่ท่าทาง/ของที่ถือ (ถือของข้างเดียว บิดตัวเล็กน้อย)
ทำให้ **ลำตัว** ซึ่งเป็นส่วนที่สายตาคนดูใช้ตัดสินว่า "อยู่กลางหรือเปล่า" เอนไปจากแนวเท้า

ถ้าตัวไหนดูเอนหลังจัดกึ่งกลางเท้าแล้ว ให้วัด centroid ของพิกเซลทึบช่วง 35–75% ของความสูงไฟล์
(คือช่วงลำตัว ไม่รวมหัวและขา) แล้วแปลงเป็นเปอร์เซ็นต์ของ**ความสูงไฟล์** (ไม่ใช่ความกว้าง — เพราะ
`background-size:contain` สเกลตามความสูงเป็นหลัก) คูณด้วยสัดส่วน figure-height/stage-width
แล้วขยับ `x` ใน roster.json ชดเชย เท้าจะเยื้องจากกลางเบาะเล็กน้อยแทน แต่คนดูจะไม่สังเกต
เพราะเท้าเป็นจุดเล็กที่สุดในภาพ ขณะที่ลำตัวคือสิ่งที่ตาจับก่อน

**การจับคู่สีเบาะ-กับ-ตัวถัดกัน ทำให้เดาขอบเบาะผิดซ้ำสองรอบ**

`document-control` กับ `the-interface` ถูกจูนตำแหน่งซ้าย-ขวาผิดมาแล้วสองรอบก่อนหน้านี้
(ครั้งแรกด้วยการเทียบสีอัตโนมัติ ครั้งที่สองด้วยการกะเปอร์เซ็นต์ครอปภาพคร่าวๆ) ทั้งสองครั้ง
ได้ค่าที่ยัง**เยื้องขวาไป 1.5–2%** — สาเหตุคือเบาะทั้งสองใบมีสีใกล้เคียงพื้นไม้มาก
(เขียวมะกอก/ทาทามิสีน้ำตาลอ่อน) การไล่สีอัตโนมัติที่ใช้ได้ผลกับเบาะสีสดอื่นๆ (ชมพู ฟ้า เหลือง)
จับขอบผิดเป็นระยะเวลานานโดยไม่มีใครรู้ตัว

วิธีที่ได้ผลจริงคือ **ซูมภาพเปล่า (ไม่มีตัวละคร) แล้ววาดเส้นกริดทุก 0.5–1% ทับ** จากนั้นอ่านขอบ
เบาะด้วยตาที่จุดที่ผ้าเบาะเปลี่ยนเป็นไม้จริงๆ (ไม่ใช่ลายทอทาทามิที่ทำให้เกิดขอบลวงเยอะมาก)
หาค่ากลางจากขอบซ้าย-ขวาที่อ่านได้ ไม่ใช่เดาจากสีหรือครอปคร่าวๆ

**สิ่งที่ตัวตัดแก้ให้ไม่ได้ — ตำแหน่ง "ลึก-ตื้น" บนเบาะ**

ข้อ 3 จัดกึ่งกลางซ้าย-ขวาให้อัตโนมัติ แต่ระยะหน้า-หลังบนเบาะ (ยืนชิดขอบหน้าหรือกลางเบาะ)
เป็นเรื่องของ `roster.json` เพียงอย่างเดียว เพราะคนละภาพกัน — ไฟล์ตัวละครไม่รู้ว่าเบาะลึกแค่ไหน

เจอสองตัว (`document-control`, `the-interface`) ที่ตั้ง `y` ไว้ตรงกับ **ขอบหน้า**ของเบาะ
แทนที่จะเป็นกลางเบาะ ทั้งที่ตัวอื่นในแถวเดียวกันตั้งไว้ที่กลางเบาะหมด — เดินตาข่ายกริดเทียบสี
จับไม่ได้เพราะเบาะกลมมีเฉดสีไล่เนียนอยู่แล้ว ต้อง **ซูมดูภาพจากเบราว์เซอร์จริงทีละตัว**
เทียบกับตัวข้างเคียงในแถวเดียวกัน ถึงจะเห็นว่าใครยืนขอบหน้า

ไฟล์ที่มีชั้นความโปร่งมาแล้ว ตัวตัดจะ**เชื่อค่าความโปร่งของไฟล์นั้น** ไม่ไปเดาจากสี
(ถ้าเดาจากสี ชุดคลุมสีขาวจะโดนเจาะทะลุ)

ส่วนไฟล์ที่พื้นหลังเป็นสีขาวทึบ ตัวตัดคีย์พื้นด้วย **flood fill จากขอบภาพ** ไม่ใช่ลบทุกพิกเซลที่ขาว
เพราะตัวละครมีสีขาวอยู่ในตัว (ชุดคลุมสีครีม โคมไฟ หน้ากระดาษ) การลบขาวทั้งภาพจะเจาะทะลุ
ส่วนขาวที่ต่อเนื่องกับขอบเท่านั้นที่เป็นพื้นหลังจริง

ถ้าตัวละครยืนชิดกันจนไม่มีช่องขาวคั่น ตัวตัดจะหาจุดที่พิกเซลบางที่สุดแล้วผ่าตรงนั้น

## สีประจำตัว (`color`) ต้องมาจากสีเบาะจริง ไม่ใช่ตั้งลอยๆ

`color` ใน roster.json คือสีเรือง (วงแสงใต้เท้า, แสงตอนทำงาน, เส้นสั่งงานในฟีด)
**ต้องเป็นสีตระกูลเดียวกับเบาะที่ตัวละครยืนอยู่** ไม่งั้นเวลาตัวนั้นทำงาน แสงที่ออกมาจะขัดกับ
สีเบาะใต้เท้ามันเอง — เคยเกิดจริงกับ `the-gatekeeper` ที่ตั้ง `color` เป็นเขียว ทั้งที่เบาะเป็นสีฟ้า

วิธีหาให้ตรง: สุ่มสีจากภาพฉากจริงที่จุดเบาะ (หลีกเลี่ยงจุดที่ตัวละครบัง) แล้วดันความอิ่มตัว/
ความสว่างขึ้นให้เป็นสีเน้นที่มีแรงเรือง โดยคงเฉดสี (hue) เดิมไว้ — ไม่ใช่เลือกสีเน้นเอาเองแล้วเดาว่าเบาะสีอะไร
ดูตัวอย่างสคริปต์ที่ใช้จริงได้ใน git log ของไฟล์นี้

**สีที่คำนวณได้แบบนี้เป็นแค่จุดตั้งต้น** — สองตัวที่เบาะเป็นตระกูลเดียวกันจริง (เช่นสองเบาะชมพู
สองเบาะฟ้า) จะได้สีออกมาใกล้กันจนแยกไม่ออกตอนเรือง ต้องปรับด้วยตาอีกรอบให้แต่ละตำแหน่งแยกจากกัน
ชัดเจน โดยยังอยู่ในโทนใกล้เคียงเบาะเดิม (ไม่ใช่เปลี่ยนไปคนละตระกูลสี) ค่าปัจจุบันทั้ง 11 ตำแหน่ง:

| ตำแหน่ง | สี |

## เพิ่มตำแหน่งใหม่เข้าห้อง

แก้ `tools/monitor/roster.json` อย่างเดียว ไม่ต้องแตะ CSS หรือ JS

```json
{
  "id": "my-role",
  "name": "MY ROLE",
  "title": "PRINCIPAL SOMETHING",
  "th": "ชื่อไทย",
  "agent": "ชื่อ agent ใน .claude/agents/",
  "x": 50, "y": 65,
  "scale": 1,
  "color": "#F0B45E"
}
```

- `x` `y` เป็นเปอร์เซ็นต์บนฉาก · **`y` คือเส้นเท้า** ให้ตรงกับผิวบนของเบาะใบนั้น
- `y < 60` ถือเป็นแถวหลัง ตัวจะเล็กลงตามระยะ และการ์ดข้อมูลจะเปิดลงแทนที่จะเปิดขึ้น
- `scale` เป็นตัวคูณขนาดของตัวละคร สำหรับเบาะที่อยู่ใกล้กล้องกว่าเพื่อนในแถวเดียวกัน
  (ใบซ้ายสุดกับขวาสุดของแถวหน้าใช้ `1.18`)
- agent ตัวเดียวมีได้หลายโต๊ะ — ระบบเลือกโต๊ะจาก path ของไฟล์ที่มันเขียนจริง
  (`developer` ใช้วิธีนี้แยกหน้าบ้านกับหลังบ้าน)
